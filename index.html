A small MCP server for reading your Markdown notes

I built this to understand the Model Context Protocol by making something real with it: an AI assistant that can search and read a folder of Markdown notes.

Get Started on GitHub See Install Steps
Why I built it

I wanted to understand MCP, not just read about it

I picked the simplest useful idea I could think of: let an assistant search and read a folder of Markdown notes. It is small enough to finish and real enough to run into the interesting problems.

Resources vs tools

A resource is something the client can read. A tool is something the model decides to call. Wiring up both made the difference click.

What stdio looks like

JSON-RPC 2.0 over standard input and output. No port, no server process to expose, which also simplifies the security story.

Access means attack surface

Handing an AI a folder is a security decision. Testing it found real gaps in my first version. More in the Security section.

Building with an AI tool

Built with IBM Bob. This is a personal project and the views here are my own.

You: "Summarize my notes on async architecture"
→ the model calls search_notes
→ the server returns the matching note text
→ the model writes the summary

The server only finds and returns text. The summarising happens in the model on the client side.

Features

What it exposes

note:///

Notes Index Resource

Lists every Markdown note in the vault as a URI, including nested subfolders.

note:///{path}

Note Resource Template

Reads one note by URI, for example note:///Work/sprint-planning.md.

search_notes

Full-Text Search Tool

Search across all .md files. Returns note titles, URIs, and the exact matching lines — up to 50 results.

get_note

Get Note Tool

Fetch a note by exact URI or fuzzy filename match. The full text goes into the model's context, and the model does the summarising.

Security

What I designed for, and what testing found

Giving an AI read access to a folder creates an attack surface, even in a toy project. This is what the code does and what I actually tested. It is not a guarantee, and it has not been audited.

🔒

Read-only

Only fs.readFile, fs.readdir and fs.realpath. No write, delete, or execute operations.

🛡️

Traversal blocked

Tested: note:///../outside.md and a sibling folder sharing the vault's name prefix are both rejected.

🚫

No network listener

Runs over stdio. No open port and no HTTP server. Only your MCP client can talk to it.

🔗

Found and fixed: symlinks

A symlink inside the vault pointing outside it could be read. Reads now resolve the real path and re-check the boundary.

👁️

Found and fixed: hidden files

The vault walker skipped dotfiles, but a direct request for note:///.env still worked. Direct reads now reject them.

📄

Found and fixed: file types

Direct reads accepted any file type. Only .md files are readable now.

Reproduce the checks with npm run security-check. It is a handful of regression checks, not a full test suite.

⚠️ One trade-off to know: When a tool returns note content, it enters your LLM's context. If you use a cloud-hosted LLM (Claude, GPT-4), that content leaves your machine. The server is local, but the LLM may not be. Use a local model via Ollama for fully local processing. Note text can also contain instructions aimed at the model (prompt injection), which the server cannot filter.
Not verified
  • Very large vaults. Search reads every file on every query.
  • Windows paths and case-insensitive filesystems.
  • Race conditions between the real-path check and the read.
  • Anything an independent reviewer would find that I have not.
Get Started

Try it in 3 steps

1

Clone and build

git clone https://github.com/alihabbache/Personal-Knowledge-MCP-Server.git
cd Personal-Knowledge-MCP-Server
npm install && npm run build
2

Register with your MCP client

Add this to your MCP config (e.g. ~/.bob/settings/mcp.json for Bob, or Claude Desktop's config file):

{
  "mcpServers": {
    "personal-knowledge": {
      "command": "node",
      "args": ["/path/to/Personal-Knowledge-MCP-Server/build/index.js"],
      "env": {
        "NOTES_DIR": "/path/to/your/notes"
      }
    }
  }
}
3

Talk to your notes

Restart your AI client and start asking in plain English:

"List all my notes"
"Search my notes for 'system design'"
"Summarize my sprint planning note"
"What have I written about product strategy?"
